● Test Areas

What gets tested

Your device is examined across four areas. Applicable tests depend on the capabilities you declare.

🔧

Hardware Security

  • Board reconnaissance and exposed entry points
  • Debug ports: JTAG, SWD, UART
  • Peripheral buses: UART, SPI, I²C, USB, RS232/485
  • Firmware extraction from flash and ports
  • Hardware bill of materials
🛡️

Firmware Security

  • Static and dynamic analysis, emulation
  • Secure boot and secure update checks
  • SBOM and third-party library CVEs
  • Binary-level reverse engineering
  • Hardening checks
📡

Communication Security

  • Ethernet, Wi-Fi, Bluetooth, Zigbee, LoRa, NB-IoT, cellular
  • Application protocols (CoAP, MQTT, domain-specific)
  • MUD profile verification
  • PCAP analysis and AI-based anomaly detection
🔐

Side-channel & Crypto

  • EM, power and timing analysis
  • Formal verification of crypto implementations
  • Privacy-preserving technique evaluation
Hardware probing tests need the physical device and are performed manually. Many firmware and communication tests are automated.

● What to Prepare

Before you place a request

Keep these ready so testing can start without delays.

1

Device detailsDomain, model, interfaces and protocols, OS type (bare metal, RTOS, embedded Linux), intended usage.

2

Target standardThe standard you want to check against, such as ETSI EN 303 645 or IEC 62443.

3

Questionnaire answersYour answers decide which security requirements and procedures apply to the device.

4

Soft artifactsFirmware image, design and architecture documents, schematics, sample captures where relevant.

5

Physical deviceUnits and accessories (cables, adapters, power) for hardware tests. Debug access details if provided.

Tip: choose only the test areas you need. You can run security, functionality, or both.

● FAQs

Security Sandbox questions

Is this the same as formal certification?

No. It is a pre-compliance check that gives you a level of assurance before certification, which is longer and costlier.

Can I choose which tests to run?

Yes. Applicable tests come from your declared capabilities, and you can pick and choose test areas.

Do I need to ship the device?

Hardware tests need the physical device. Firmware and communication tests may work with artifacts alone.

Which standards are supported?

Procedures are standard-agnostic and map to ETSI, NIST, OWASP, STQC, AIS, ISO/SAE, IEC 62443 and IEC 60601-4-5.

Is my firmware kept confidential?

Please confirm the confidentiality terms with the team before submitting sensitive artifacts.
